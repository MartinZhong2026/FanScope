# Paper Diagnostic（论文诊断）· D1/D2 第一版

状态：代码与自动化验收已完成；**生产默认关闭**（`FANSCOPE_DIAGNOSTIC_ENABLED` 未设置时所有 `/api/diagnostic/*` 返回 404，页面显示“尚未开放”）。

## 用户流程（真实页面）

课题组登录 → 工作台右上角“论文诊断”（`/lab/diagnostic.html`）→ 上传 PDF / DOCX / Markdown / TXT（≤10MB，不支持扫描版；上传框上方会写明哪位导师可以查看）→ 阅读并勾选授权说明（同样写明导师可见）→ 开始诊断 → 查看报告 → 可共享、重新诊断或删除。历史记录列在左侧。

报告分三部分：
1. **稿件事实**：研究问题、理论、假设、数据、方法、结果、结论，每条都附原文摘录，并经服务端逐字核对；无法在原文中找到的条目会被剔除并计数。
2. **问题与修改建议**：按 严重 / 重要 / 次要 排序，包含证据摘录、审稿人可能的追问和可执行建议。没有可核对原文的条目会标注“推断”。
3. **分维度检查**：按论文类型给出。定量研究检查变量、样本、模型、推断、因果表述、稳健性；定性研究检查抽样、资料收集、分析、反身性、诠释。

## 引擎

| `FANSCOPE_DIAGNOSTIC_PROVIDER` | 说明 |
| --- | --- |
| `rules`（非生产默认） | 关键词规则演示引擎，不调用任何外部服务；报告明确标注“演示模式”，不冒充 AI |
| `deepseek` | 真实 AI 引擎，分两步（结构识别 → 诊断），稿件全文作为稳定前缀以利用 DeepSeek 上下文缓存。所有调用经统一 LLM 客户端 `platform/llm.mjs`（K4 最小版）：先在 `llm_calls` 账本中登记再发送（只记元数据），用幂等键防止同一请求重复发送，最多尝试 2 次且只重试 429/5xx/网络错误，有全局并发上限（`FANSCOPE_LLM_CONCURRENCY`）和熔断机制。需 `DEEPSEEK_API_KEY`；每人每日上限 `FANSCOPE_DIAGNOSTIC_DAILY_LIMIT`（默认 5） |
| 未设置（生产） | `none`，诊断请求返回 503 |

授权按引擎记录：对规则引擎的同意**不能**用于 DeepSeek，切换引擎后须重新同意。

## 权限与隐私（服务端强制）

课题组只有一位导师，因此权限按单导师设计，复用现有的 Lab 角色（`member` / `mentor` / `lab_admin`）：

- **可访问者**：
  - 上传者本人。
  - 上传者显式共享的成员。
  - 课题组**唯一指定导师**：由 `lab_admin` 在页面中指定，保存在 `meta` 的 `diagnostic:trusted-mentor` 中，必须是在职的 `mentor` 账号。
  - 其他人（包括其他 `mentor` 账号和 `lab_admin` 本人）一律 403。
- **指定权**：只有 `lab_admin` 能指定或取消导师；导师不能指定自己或他人，普通成员不能操作。现有 Lab 账号体系中，成员无法创建账号或修改角色，只有导师能新建导师账号；但新建的导师账号不会获得诊断访问权限。更换导师会写入 `notice` 级日志，并对全部稿件生效。
- **告知**：上传框和授权文字都会写明“课题组导师（姓名）可以查看你上传的稿件信息和诊断报告”。未指定导师时，写明没有导师可见。
- **操作权限**：诊断、授权、共享、删除只有上传者本人可做；导师只能阅读。
- **保留期限**：
  - 原稿文件与提取文本保留 14 天，报告保留 90 天，从上传时计。
  - 每次读取都检查期限，过期返回 410。
  - 物理删除由 `purgeDue()` 执行（每次诊断请求顺带执行，另有每小时定时器），可重复执行。
  - 报告到期后，标题和文件名也一并清空。
- **主动删除**：立即删除文件、文本和全部报告，共享对象同时失去访问权限。诊断进行中被删除时，本次结果丢弃并记为 `cancelled`。
- **日志**：只记录 id、引擎、错误码和耗时，不记录正文、提示词或模型输出；测试会检查日志中不含稿件句子。
- **浏览器安全**：页面使用独立的严格 CSP（`web/_headers`，`/lab/diagnostic*`），不使用内联脚本。

## DeepSeek 质量评测

`scripts/dx-quality-eval.mjs` 用 `api/test/fixtures/dx-eval/` 中的 3 篇**合成稿件**评测诊断质量：中文定量、中文定性、英文定量，每篇都预埋了已知缺陷。评测使用生产环境同一套提示词、引擎和校验逻辑，指标包括：

- 预埋缺陷召回率；
- 严重度是否达标；
- 事实引文核对通过率；
- 论文类型准确率；
- 被剔除的引文数；
- tokens 用量与耗时。

结果写入 `work/dx-eval/`，供人工逐条阅读。

- 规则引擎基线（免费）：召回率 0.167，事实核对 1.0，类型准确率 1.0。
- DeepSeek 运行属于付费调用，必须加 `--confirm-paid` 并设置 `DEEPSEEK_API_KEY`，否则脚本拒绝运行。只发送上述合成稿件。
