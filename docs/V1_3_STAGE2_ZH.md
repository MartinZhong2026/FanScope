# FanScope v1.3 Stage 2 · 深色科研工作台 / 期刊来源可视化管理

## 交付来源和兼容性
本阶段严格继承 `FanScope_v1.3_Stage1_ReadyForGitHub.zip` 的所有源码文件，不重置第一阶段的 `analysis_batches`、缓存、Token 成本表、Lab 账号权限、论文数据表，也不改 Docker 持久化卷。前端保持原生 JS + HTML + CSS + 已内置的 Apache ECharts，不迁移到 Next.js/React，不引入收费云组件。

## 已完成改动
1. 新建 `web/theme.js`：默认深色，浅色和跟随系统可切换，偏好保存在用户自己浏览器 localStorage；支持系统颜色偏好变化时更新。`web/index.html` 和 `web/lab/index.html` 均提前载入主题，以减少白屏闪烁。
2. 增加独立的 `web/stage2.css` 和 `web/lab/stage2.css`，统一背景、层级、圆角、间距、字体颜色、按钮、输入框、状态、数据表、论文条目、任务区域；桌面导航不变，手机使用四栏底部导航，原有长列表压缩为紧凑视图。
3. 首页引入 **6 个真实入口**：最新论文、研究趋势、期刊画像、来源监测、期刊配置、课题组协作；保留原首页真实论文计数、简报和原有统计；没有填充假数据。
4. 新增「期刊来源管理」页面：从服务器公开的 `/api/journal-source-status` 获取候选、已启用、成功、失败的真实状态。管理员可逐本输入 ISSN，点击「检测来源」调用 Stage 1 `POST /api/admin/journal-source/test`，人工确认后点击「核验并启用」调用 `/activate`。每次都临时询问管理员密钥，不写入 localStorage、Cookie 或源码；验证失败保持候选状态。中文期刊不允许盲目用 Crossref 激活。启用也不伪称完成首次扫描。
5. ECharts 图表响应深浅色主题，统一轴标签、网格、热力图配色与提示框；分析维度如果有效证据数是 0，显示明确的缺失状态。此前已存在的 7 个图表及其统计口径继续保留。
6. UI 仍通过原 `/api/stats`、`/api/journals`、`/api/articles`、`/api/research`、`/api/system-status` 和 Stage 1 新增的状态接口获取数据。没有绕过 API 或改写现有文章计数。

## 查看和手动测试
1. `cd web` 后使用任意静态文件服务提供 `index.html`；需先确认 `web/config.js` 中 API 地址是**用户自己的后端地址**。
2. 浏览器打开首页，主题按钮循环：深色 → 浅色 → 跟随系统；刷新后偏好仍在。
3. 进入「期刊来源管理」，初始候选保留「待接入」，测试后也不直接修改启用状态；确认启用需要管理员口令。注意该操作会更改后端数据，生产环境只对已核对 ISSN 的期刊执行。
4. 进入「研究趋势」：零证据维度仍为明确的空状态；切换主题后图表刻度、提示框可读。
5. 进入 `/lab/` 检查成员登录、项目、稿件、Word/PDF 纪要和权限未受影响。
